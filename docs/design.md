# Design note

The service uses Go and PostgreSQL, with the database acting as the durable queue. `docker compose up --build` starts migrations, the API, and four independent workers. The chaos harness starts eight worker processes against its own fresh schema. PostgreSQL provides row locks, transactions, unique keys, and durable job state in one system; adding a broker would introduce a second write that must be reconciled. Jobs simulate training with a timer and a countable database effect row.

**Claim and scheduling.** A single update selects the oldest eligible queued job by `(created_at,id)` with `FOR UPDATE SKIP LOCKED`, marks it running, assigns ownership, increments the claim version and attempt count, and grants a ten-second lease. The implicit transaction ends before execution. Skipping locks permits concurrent progress; this is approximate FCFS claim order, and completion order can differ. Workers execute one job at a time and renew every two seconds.

**Crash recovery and stale workers.** All expiry decisions use PostgreSQL `clock_timestamp()`. Renewal, success, and failure lock the job row, verify running state, worker ID, and claim version, then check actual database time after acquiring the lock. The lock reserves that validated transition until commit or rollback. A separate loop scans expired leases every second, locks a bounded batch, rechecks expiry, clears ownership, and increments the version. It requeues jobs with attempts remaining and marks jobs failed with `attempts_exhausted` after five attempts. A resumed worker cannot use its old token even if its ID is reused. Recovery needs an available database and a surviving or restarted worker; a lease does not stop a paused process from running.

**Cancellation.** The API locks the same row. Queued/running jobs become cancelled immediately in durable state, ownership is cleared, and their claim version changes. Workers observe cancellation during renewal or finalization and abandon execution. If success commits first, cancellation returns 409. If cancellation commits first, success is rejected. A repeated cancellation returns the existing cancelled job; it cannot undo a committed effect.

**Guarantees and transactions.** Execution attempts may repeat after a crash. Success inserts the unique `job_effects` row and writes the succeeded state in one transaction. Either both persist or neither does. Consequently successful jobs have exactly one committed simulated database effect; failed/cancelled jobs have none. This is at-least-once attempts with an exactly-once database effect for success, not exactly-once computation or an external-effect guarantee. Explicit execution failures are terminal. Network failures abandon ownership for lease recovery. An uncertain commit is reconciled with a fresh bounded read of status and claim version; effects are never blindly repeated.

**API correctness.** A unique idempotency key serializes concurrent creation. Conflicting inserts read the winning row in a fresh statement and compare normalized input. Keys remain attached to jobs after cancellation or failure. Lists use timestamp/UUID keyset cursors carrying the status filter. READ COMMITTED transactions, row locks, conditional writes, and uniqueness enforce the protocol; a transaction is never held during simulated execution.

**Evidence and verdict.** Independent audits compare every manifest key, payload, terminal state, ownership, accepted cancellation, and effect count/version. Targeted tests cover selected race windows; random SIGKILL cannot exhaust all schedules. Three fingerprinted corrected-harness chaos runs passed their audits (earlier batches are also preserved) and the mixed 100 RPS load passed. At 100 unique creations/second, eight workers fell behind by about 32 jobs/second, although the final audit passed after drain. The full PostgreSQL race-test suite, paused-worker/heartbeat cases, and Compose readiness/restart/persistence verification subsequently passed. The current decision is DON'T SHIP at an unrestricted 100 RPS; see `verdict.md` and `evidence.md` for measurements and preserved failures.
